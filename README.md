# نبض — تطبيق اختبارات عربي 

تطبيق Next.js لإنشاء وإجراء الاختبارات (MCQ وصح/خطأ) باللغة العربية. يتضمن التطبيق واجهة الطالب لإجراء الاختبارات، ولوحة للمدرّس لرفع الاختبارات بصيغة JSON ومعاينتها قبل نشرها.

## التشغيل في وضع التجربة (Demo)

```bash
npm install
npm run dev
```

افتح `http://localhost:3000`. لا تحتاج إلى قاعدة بيانات أو مفاتيح للتشغيل في الوضع المحلي؛ سيتم توفير اختبارات جاهزة وتُحفظ البيانات في `localStorage` داخل المتصفح. رقم دخول المدرّس التجريبي هو `1234`.

## تفعيل قاعدة البيانات (Supabase)

لنشر حقيقي متعدد المستخدمين، يدعم التطبيق التخزين السحابي عبر Supabase:

1. أنشئ مشروعًا جديدًا في [Supabase](https://supabase.com/).
2. شغّل أوامر SQL الموجودة في ملف `supabase-schema.sql` في محرر SQL الخاص بـ Supabase لإنشاء الجداول والقيود المطلوبة.
3. انسخ `.env.example` إلى `.env.local`.
4. ضع الرابط ومفتاح `service_role` في `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY`. (ملاحظة: هذا المفتاح يعمل على الخادم فقط ولا يُرسل للمتصفح).
5. غيّر `ADMIN_PIN` قبل مشاركة التطبيق لحماية لوحة المعلم.
6. أعد تشغيل `npm run dev`.

## نشر تحديث الإدارة والنتائج

1. على قاعدة البيانات الحالية شغّل `supabase-admin-reports.sql` فقط بعد وجود الجداول الأساسية. للمشروع الجديد شغّل `supabase-schema.sql` أولًا. التحديث لا يحذف أو يعدّل المحاولات.
2. في Vercel → Settings → Environment Variables أضف `ADMIN_PIN` بكلمة مرور قوية (حتى 64 حرفًا)، وأضف `ADMIN_SESSION_SECRET` بقيمة عشوائية مستقلة. أدخل القيم مباشرة هناك ولا ترسلها في المحادثة.
3. احذف `NEXT_PUBLIC_ADMIN_PIN` إن وُجد. لا تضف بادئة `NEXT_PUBLIC_` لأي سر. احتفظ بإعدادات Supabase الحالية.
4. أعد نشر التطبيق لتفعيل القيم. غياب `ADMIN_PIN` في production يمنع دخول الإدارة. تغيير كلمة المرور أو سر الجلسة يبطل الجلسات السابقة.
5. ادخل من `/#admin`، ثم «نتائج الطلاب». يعرض التقرير كل المحاولات المسلّمة فقط، بالتوقيت المحلي للقاهرة، مع صفحات للطلاب ولكل سجل محاولات. الاسم بعد توحيد الحروف والمسافات هو هوية الطالب؛ الأسماء المتطابقة تُجمع.

واجهة الدخول تعرض الرقم التجريبي 1234 دائمًا، لكنه لا يكشف كلمة مرور الإنتاج ولا يستبدلها. محليًا فقط يُستخدم 1234 إذا لم تُحدد كلمة مرور. استعلام التقرير متاح لمفتاح السيرفر `service_role` فقط، ولا يعيد إجابات الطلاب الخام. إن لم يُطبق SQL الجديد تظهر رسالة خطأ وإعادة محاولة بدل نتائج ناقصة.

يمكن تشغيل `supabase-admin-reports.test.sql` على قاعدة اختبار بعد التحديث للتحقق الفعلي من أكثر من 1000 محاولة وصلاحيات RPC. الاختبار يستخدم transaction ثم rollback؛ لا تشغّله على الإنتاج.

## رفع الاختبارات (JSON)

تعتمد لوحة المدرّس على رفع ملفات JSON بصيغة محددة. مثال:

```json
{
  "title": "اختبار المجموعة الشمسية",
  "unit": "الفضاء",
  "description": "اختبار مبسط",
  "durationMinutes": 5,
  "questions": [
    {
      "type": "mcq",
      "text": "ما أكبر كواكب المجموعة الشمسية؟",
      "options": ["الأرض", "المشتري", "المريخ", "زحل"],
      "correctIndex": 1,
      "explanation": "المشتري هو أكبر الكواكب."
    }
  ]
}
```

## التحقق

### الأكواد متعددة الأسطر

تدعم نصوص الأسئلة والخيارات والشرح كتل كود بين ثلاثة backticks، مثل `javascript` أو `js` أو `python` أو `py` أو `html` أو `css` أو `json`. ابدأ السياج وأنهِه في سطر مستقل. داخل ملف JSON استخدم `\n` للأسطر و`\t` للتبويب و`\"` للاقتباس الداخلي. مثال جاهز: [public/code-quiz-example.json](public/code-quiz-example.json)، متاح أيضًا للتنزيل من لوحة المدرّس.

المسافات والأسطر محفوظة دون حذفها عند الاستيراد أو الحفظ. الحد الأقصى للسؤال والشرح 10,000 حرف وللخيار 4,000 حرف، وحجم الملف 512 كيلوبايت. اللغات غير المدعومة أو غير المحددة تظهر ككود عادي، والسياج غير المغلق يظهر كنص كامل. الأكواد للعرض فقط ولا تُنفّذ.

```bash
npm test
npm run typecheck
npm run build
```
